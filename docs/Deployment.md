# Deployment & Production Orchestration Guide

This document describes how to deploy the **Intelligent Autonomous Agentic AI ETL Platform** into a production container environment.

---

## 1. Prerequisites
Ensure you have the following installed on the target server:
- **Docker** (v20.10 or higher)
- **Docker Compose** (v2.0 or higher)

---

## 2. Setting Up Environment Secrets
Create a `.env` file in the root directory:
```bash
# Database parameters
MYSQL_HOST=db
MYSQL_PORT=3306
MYSQL_DB=agentic_ai_etl
MYSQL_USER=etl_user
MYSQL_PASSWORD=etl_password

# Staging database parameters
STAGING_MYSQL_DB=agentic_ai_etl_staging
STAGING_MYSQL_USER=etl_user
STAGING_MYSQL_PASSWORD=etl_password

# LLM setup
GEMINI_API_KEY=your_gemini_api_key_here
LLM_PROVIDER=gemini # fallback to ollama or mock if empty
OLLAMA_HOST=http://ollama:11434
```

> The compose stack runs with `ENV=production`, so also set `DEFAULT_ADMIN_PASSWORD` to a strong
> password (12+ characters). With the default `admin`, no administrator account is created.

---

## 3. Running with Docker Compose

To build images and launch the containers:
```bash
cd docker
docker-compose up --build -d
```

### Container Status Verification:
```bash
docker ps
```
Verify that all 5 services are running:
- `etl_backend` (port 8000)
- `etl_mysql` (port 3306)
- `etl_ollama` (port 11434)

---

## 4. SnapLogic IIP Workflow Configuration

SnapLogic (Commercial Intelligent Integration Platform - SnapLogic IIP) acts as the scheduled trigger, Iris AI assistant coordinator, and visual pipeline orchestrator.

### Snaps Configuration:
1. **File Reader Snap**: Configure a `FileReader` snap pointing to `/data/raw` to scan files every 5 seconds.
2. **Iris AI Intake Snap**: Resolves file formats and triggers Agent 1 schema profiling via `http://backend:8000/api/v1/pipeline/intake`.
3. **Data Transformation Snap**: Cleans datasets, standardizes headers, and imputes nulls via `http://backend:8000/api/v1/pipeline/transform`.
4. **SQL Staging & Format Snap**: Selects optimal storage format and loads MySQL staging tables via `http://backend:8000/api/v1/pipeline/store`.
5. **Word Docx Exporter & AI Report Snap**: Exports cleaned Word `.docx` files and compiles analytical reports via `http://backend:8000/api/v1/pipeline/report`.
6. **Power BI Gateway Snap**: Triggers automated Power BI dataset synchronization via `http://backend:8000/api/v1/powerbi/refresh`.
7. **FileWriter Archive Snap**: Move the completed raw inputs to `/data/archive`.

## 5. Deploying to Render

`render.yaml` in the repository root is a Render Blueprint: one Docker web service built from
`docker/Dockerfile.backend`, with a persistent disk for all runtime data.

### Steps
1. Push the repository to GitHub (already done for `Vikaskaushal-01/ETL`).
2. In the [Render dashboard](https://dashboard.render.com/) choose **New > Blueprint** and select the repository,
   or use the **Deploy to Render** button in the README.
3. When prompted, fill in:
   - `DEFAULT_ADMIN_PASSWORD`: the password for `admin@controlai.net` (12+ characters, required).
   - `GEMINI_API_KEY`: optional; without it the offline reasoning engine is used.
4. Apply. The first build takes a few minutes; the app is then live at
   `https://control-ai-etl.onrender.com` (or the name Render assigns if that is taken).
5. Sign in as `admin@controlai.net` with the password from step 3.

### What the blueprint sets up
| Setting | Value | Why |
| :--- | :--- | :--- |
| Plan | `starter` | Persistent disks need a paid instance |
| Disk | 1 GB at `/var/data` | Uploads, cleaned data, reports, logs and the SQLite database |
| `STORAGE_DIR` | `/var/data` | `docker/entrypoint.sh` links the runtime folders onto the disk |
| `ENV` | `production` | Disables demo social login and demo reset codes |
| `SECRET_KEY`, `SERVICE_API_KEY` | generated by Render | Session signing and the SnapLogic API key |
| Health check | `/api/v1/health` | Returns 503 when the database is unreachable |

Render provides `$PORT` and HTTPS; the container listens on that port with proxy headers enabled.

### Free plan (demo only)
Set `plan: free` and delete the `disk` block in `render.yaml`. The app works, but free instances have
no persistent disk: accounts, uploads and run history are lost whenever the instance restarts or
sleeps after inactivity.

### Using MySQL instead of SQLite
Set `MYSQL_HOST`, `MYSQL_PORT`, `MYSQL_DB`, `MYSQL_USER` and `MYSQL_PASSWORD` (or a full `DATABASE_URL`)
in the service's environment. The disk is still used for uploaded files and reports.

### Scaling
SQLite and the uploaded files live on one disk, so keep a single instance (`numInstances: 1`).
